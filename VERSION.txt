v2.3 — 2026-08-12

FIX: pyproject.toml exigía Python >=3.11, lo que bloqueaba por completo
`pip install -e .` en Python 3.9.6 (el entorno real donde ya se había
confirmado que las 74 pruebas pasan). Se relajó a >=3.9 — la
recomendación de actualizar a 3.11/3.12 sigue en pie (ver README), pero
ya no es un bloqueo técnico, solo una sugerencia. Se verificó que el
código no usa ninguna sintaxis exclusiva de Python 3.10+ que
justificara el límite anterior.

- Nuevo: VALIDACIÓN DE CONFIGURACIÓN CON PYDANTIC:
  -> core/config.py — AgentConfig ahora es un pydantic.BaseModel en vez
     de un @dataclass simple. Un valor inválido (umbral_critico=-5,
     split_ratio=1.5, n_pca_components=0, idioma_reporte="fr", etc.)
     falla AL CONSTRUIR el objeto, con un mensaje que identifica el
     campo, el valor recibido y por qué está mal — no minutos después,
     a mitad del entrenamiento.
  -> extra="forbid": un typo en el nombre de un parámetro
     (umbral_critco en vez de umbral_critico) también falla, en vez de
     ignorarse en silencio.
  -> El CLI (plc-agent / orchestrator.py main()) captura estos errores
     y los muestra limpios, sin traceback, con código de salida 1.
  -> Todas las restricciones de validación están justificadas por cómo
     se usa cada campo en el código real (ver comentarios en
     core/config.py) — no son límites arbitrarios.
  -> tests/test_config_validation.py — 30 pruebas nuevas dedicadas
  -> Migración 100% compatible hacia atrás: se auditaron todos los
     puntos de construcción de AgentConfig en el proyecto antes de
     migrar; ninguno mutaba atributos después de construir ni usaba
     funciones específicas de dataclasses — cero cambios necesarios
     en el código que ya usa AgentConfig(...)
